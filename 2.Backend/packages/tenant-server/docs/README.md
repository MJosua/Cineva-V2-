# @hots/tenant-server 0.1.0-cineva.1

New local Cineva package; no Kantor source changes. Shared contracts are the universal local snapshot in `1.Frontend/packages/tenant-contracts`, consumed without React. Repository-source dependencies must be included in deployment, or use the isolated bundle check under knowledge. The old flat API zip omits sibling packages and must not be treated as a complete tenant-platform release.

## APIs and trusted adapters

- `createTenantEngine`: authenticated active identity, server-resolved program, current membership/permission/version and opaque session-bound context IDs. Context TTL is finite. No anonymous context or implicit company. Repository get/list/update and brand revalidate membership before use; update rechecks before transaction callback completes. Per-row owner validation is defense-in-depth; database COUNT/filter/pagination and parent/child constraints belong inside the persistence adapter.
- `engine.invitations`: invitation tokens are hash-only in storage, bound to user/program/company, expire after 24h and require current delegation policy. Acceptance requires transactional row lock + unique membership grant + mark accepted. Caller roles/permissions are not trusted. Role resolver MUST re-read issuer authority at acceptance. Existing-member behavior/role merges must be defined by grant adapter; do not overwrite privileges implicitly.
- `createRegistrationService`: verified identity resolver + transactional user creation. Self registration creates active personal Client with no company grants. Identity uniqueness/credential verification/account recovery depend on the canonical identity adapter; do not merge by email alone.
- `createUnitOfWork`: wraps existing transaction-kit, same connection begin/commit/rollback/release, no automatic retry/idempotency schema. Inject SSE-compatible logger. Business outbox/idempotency must be supplied where required; no events should be emitted before commit.
- `createMysqlMemberships`: read-only SQL based on physical HOTS snapshot 2026-10-21. Requires explicit program ID/permission-module registry. Uses active user/company/program access, revocation flag, company permissions and optional **explicit scoped** role policy. Duplicate access rows fail closed. Does not infer access from user.role_id, company profile or null SSO allowlist. Empty access table means no companies.
- `createOidcBridge`: server-owned state/nonce/PKCE verifier, fixed HTTPS endpoints and redirect URI, atomic one-use transaction store. Inject a real cryptographic RS256 verifier (e.g. jwt.verify with trusted JWKS lookup); bridge independently validates issuer/audience/azp/nonce/time/opaque subject. Never use JWT decode as verifier. No token returned to browser. No discovery/JWKS/MFA/refresh/global logout service is implied by this adapter.
- `createAppSessionManager`: per-app __Host HttpOnly Secure SameSite=Lax opaque session cookie, separate readable CSRF cookie, exact Origin/header CSRF checks, finite absolute lifetime, current global-user active check on requests, application logout revocation. Inject persistent shared session storage; in-memory stores are fixtures only. No global active-company mutation. Distributed/global device logout and idle refresh remain future integration.

## Composition

Activation follow-up (2026-10-21): registry/mysql-stores/mysql-tickets/company-scope/mysql-company-scopes subpaths add explicit program binding, real transactional store adapters, hierarchy grants and read-only ownership joins. Four additive tables are now applied in the authorized HOTS database. See knowledge architecture/saas_pilot_activation_2026_10_21.md for physical DDL, Kevin Excom scope, 103/108 program mappings and live rollback evidence. Integrated-API persistentRuntime.js composes these adapters without startup side effects. Production runtime and issuer activation are still pending; old business routes do not consume these grants automatically.

App factory is `Integrated-API/app/modules/tenant-platform/runtime.js`. Caller supplies adapters explicitly. `registerRoutes(app, {tenantRuntime, tenantLogger})` mounts `/api/tenant/v1`; the normal startup currently passes no runtime and returns 503 on this new API. There is no insecure fallback to fixture accounts or unverified JWT payload. Router catches standard errors, returns no-store envelopes, and never logs credentials/tokens. Legacy endpoints retain existing behavior and are not protected by this additive mount.

SSO start/callback require `runtime.oidc`, `runtime.sessions`, `runtime.identityService.resolveOrRegister`; the latter maps issuer+subject or runs personal registration transaction without granting company access. Context POST and invitations require the mutation verifier. Persistent transaction/context/session/invitation stores need explicit TTL, cleanup, locking and revocation across workers. `createTenantRuntime` accepts injected SSO/session/identity adapters; invitation service can be attached after creation through `runtime.engine.invitations(...)`.

User decisions: future domain `cineva.com`; personal Client account immediately active, company/campaign through invitation. Domain does not prove issuer endpoint, callback registration, certificate, deployment or IdP ownership. All of those need activation configuration and runtime acceptance.
