# @hots/domain-kit

Generic implementation originating from Cineva requirements. Pure TypeScript, no React, database, localStorage, HTTP, vendor names or implicit logging. Source exports follow the existing HOTS workspace pattern.

Capabilities: typed attribute validation, structured rule issues, configurable object relations, authorized command registry with revision guards, explicit transaction/outbox ports, configuration/capability manifests, immutable config snapshots and projection selectors. See validation.md and runtime.md for exact contracts and examples across unrelated domains.

Caller owns policies, names, field mapping, identity, transactions and persistence. A client authorization callback is not server security. A transaction adapter must atomically commit domain writes and outbox entries; in-memory tests do not prove database durability. Events are delivered at least once unless a consumer/provider supplies its own deduplication guarantee. No functions or source code are evaluated from user JSON.

Cineva is the first consumer via adapters in its feature folders. Existing form/workflow/ticket engines remain authoritative for their responsibilities. No SQL/schema is generated by this package; EAV metadata is not renamed or replaced.
