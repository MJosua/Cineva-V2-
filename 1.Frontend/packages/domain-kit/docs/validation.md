# Generic document validation

These pure TypeScript utilities have no React, database, currency or vendor dependency. They do not write to inputs or evaluate source strings. Domain adapters retain their existing HOTS ticket/EAV and persistence contracts.

`Issue` is `{ code: string; path: string; message: string }`. Paths use dot-separated own-property segments. Prototype keys, inherited fields and getters are not read by `safeRead`. String content is data, including HTML-like source text; UI consumers must render it as text.

`createRules<T>(rules, options?)` returns `(data: T) => Issue[]`. A rule has `{ code, path?, message, check }`. Every check receives a separate structured clone of the original document: mutation or exceptions in one check cannot modify caller input or influence another check. Rules must return literal `true` to pass. Checks remain trusted application functions; they must not mutate external state. Inputs are data-only structured-cloneable documents; functions and unsupported runtime objects fail closed with `rule_clone_failed`. An optional `options.clone(data)` may supply an equivalent isolated deep copy on runtimes without `structuredClone`; this trusted adapter must never return caller-owned references. Exceptions become failures. Invalid configuration yields an issue. Rule metadata/order are captured when creating the validator. `assertRules(issues)` throws `RuleValidationError` carrying copied issues if any exist.

`validateRelations(collections, config)` receives named row arrays. Declare every collection in `config.collections` with optional `idField` (default `id`). IDs must be non-empty strings or safe integers; numbers and strings are distinct identifiers. IDs are unique within each collection. Unknown/missing collections and malformed rows produce issues.

Each `config.references` entry declares `{ from, field, to, targetField?, optional?, scope? }`. The target field defaults to the target collection ID field. Optional references may be null, empty or absent; supplied values still require a target. Scope is `{ sourceField, targetField }` and requires exact scalar equality in addition to the referenced value. This supports hotel+room references. Multiple targets matching a reference produce `ambiguous_reference`. No evaluation or predicate strings are supported.

`validateAttribute(value, config)` supports `integer`, `number`, `money`, `text`, `tag`, `date`. Config also accepts `path`, `required`, `min`, `max`, and `allowed` string choices. Numeric input is never coerced from text. Integer/money values must be safe integers. Money uses the adapter's declared minor unit; set `min: 0` where negative amounts are prohibited. Number permits finite fractions. Text/tag bounds are string lengths. Dates are actual calendar dates in `YYYY-MM-DD` format. Null, undefined and empty strings are permitted only when not required.

These helpers validate document consistency, not authentication or tenant security. Callers must supply configured ownership references and enforce authorization at the persistence boundary. Rule callbacks are executable application code, never imported from user documents.
